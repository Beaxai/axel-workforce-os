Phase 9: Network Module & Agent Registration Flow
Context: Phases 1–8 are complete. The app has AppShell, full component library, Marketplace, Pipeline, Deal Card Modal, Accounts, Implementations, and Billing. Phase 9 builds the Network module — the multi-party ecosystem view — and the full agent/partner registration flow. All UI must use AppShell and /components/ui/.

PART A — NETWORK MODULE
Route: /network
Accessible to: Admin, CSA roles only.
Page layout:

SectionHeader: "Network", subtitle showing total partner count
Four tabs: Agents | Carriers | PEO Partners | Vendors
Each tab shows a list of partners in that category as GlassCards
PinkButton "Add Partner" in top right — opens Add Partner modal (manual entry, for internal use)


AGENTS TAB
Each agent card displays:

Agent / agency name (bold, white)
License state(s) (muted text)
Status badge: Active / Pending / Suspended (Badge component, solid colors — Active = green #1EE97B, Pending = yellow #E9C31E, Suspended = red #E91E1E)
Deals referred count
Total WC premium referred
Click → opens Agent Detail page at /network/agents/[id]

Agent Detail page (/network/agents/[id]):

Full profile: name, agency, license states, contact info, NPN number
Registration status + dates (application submitted, agreement signed, onboarding call completed, credentials issued)
Associated deals list (links to DealCardModal)
Commission summary (placeholder for now — commission module is future phase)
GhostButton "Edit" — inline edit, saves to Supabase
GhostButton "Suspend Agent" — sets status to Suspended


CARRIERS TAB
Each carrier card displays:

Carrier name
States active in
Status badge: Active / Inactive
Bound policies count
Total premium volume
Click → Carrier Detail page at /network/carriers/[id]

Carrier Detail page:

Carrier name, AM Best rating, contact info, appetite notes (freeform text)
List of bound policies with this carrier (from policies table)
GhostButton "Edit"


PEO PARTNERS TAB
Each PEO partner card displays:

PEO name
Program name (e.g. "Kind PEO Program")
Verticals served
Active client count
Status badge: Active / Inactive
Click → PEO Partner Detail page at /network/peo/[id]

PEO Partner Detail page:

PEO name, program name, verticals, contact info
Active client organizations list

GhostButton "Edit"


VENDORS TAB

Simple list — vendor name, category, contact info, status badge
No detail page required — inline edit on the card is sufficient

PART B — AGENT REGISTRATION FLOW
This is the self-service registration funnel that external agents/partners enter through. It is a public-facing multi-step flow — it does NOT require login.
Entry point: Public route at /register/agent (no auth required)
This simulates the flow that would be reached via axelins.com. Build it as a standalone multi-step form outside of AppShell — it has its own layout with the Axel brand but no nav.

STEP 1 — Basic Information
Fields:

First Name, Last Name
Agency Name
NPN (National Producer Number)
License States (multi-select dropdown, all 50 states)
Email Address
Phone Number
PinkButton "Next"


STEP 2 — Application Review (Admin side)
After Step 1 submission:

Save to Supabase agent_registrations table with status Pending Review
Show applicant a confirmation screen: "Your application has been submitted. An Axel team member will review and contact you within 1–2 business days."
In the Admin dashboard (/dashboard/admin), add an "Agent Applications" section showing pending registrations with Approve / Reject buttons
Approving sets status to Agreement Pending and triggers Step 3


STEP 3 — HelloSign Agreement

On approval, the applicant receives an email (log to console for now — actual email delivery is a future integration) with a link to complete their agency agreement
Build a placeholder screen at /register/agent/agreement/[id] that shows: "Your application has been approved. Please sign your agency agreement below." with a GhostButton "Sign Agreement (HelloSign — coming soon)"
On clicking the button: set status to Onboarding Call Pending, log to console


STEP 4 — Zoom Onboarding Call Gate

Placeholder screen at /register/agent/onboarding/[id]
Message: "Please schedule your onboarding call with the Axel team to complete your registration."
GhostButton "Schedule Call (Calendly — coming soon)"
Admin can manually mark the call as complete in the agent registration record — adds a "Mark Call Complete" button on the admin-side registration detail
On marking complete: status moves to Credentials Pending


STEP 5 — Credential Issuance

Admin-side only — in the registration detail view, a PinkButton "Issue Credentials"
On click: creates a user account in Supabase Auth with role Agent, sets registration status to Active, links the new user to the partners table record
Show admin a confirmation with the new agent's login credentials (email + temp password)


Supabase — agent_registrations table:
id                    uuid, primary key
first_name            text
last_name             text
agency_name           text
npn                   text
license_states        text[]
email                 text
phone                 text
status                text  ('Pending Review', 'Agreement Pending', 'Onboarding Call Pending', 'Credentials Pending', 'Active', 'Rejected')
partner_id            uuid  references partners(id)  (set on credential issuance)
user_id               uuid  references auth.users    (set on credential issuance)
applied_at            timestamptz, default now()
approved_at           timestamptz
agreement_signed_at   timestamptz
call_completed_at     timestamptz
credentials_issued_at timestamptz
