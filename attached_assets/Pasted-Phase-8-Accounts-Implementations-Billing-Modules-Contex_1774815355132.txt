Phase 8: Accounts, Implementations & Billing Modules
Context: Phases 1–7 are complete. The app has AppShell, full component library, Marketplace, Pipeline with Kanban, and a working Deal Card Modal. Phase 8 builds three new modules: Accounts, Implementations, and Billing. All must use AppShell as wrapper and /components/ui/ for all components.

PART A — ACCOUNTS MODULE
Route: /accounts
Accessible to: Admin, CSA roles only.
Page layout:

SectionHeader: "Accounts", subtitle showing total account count
Search bar (text input, glass surface) — filters accounts by name in real time
Filter row: All / Active Clients / Prospects / Inactive — toggle Badge buttons
Account list rendered as GlassCards in a grid (2 columns desktop, 1 mobile)

Each account card displays:

Business name (bold, white)
Account type badge: Prospect / Active Client / Inactive (Badge component, solid colors)
Vertical + state (muted text)
WC Premium (if rated)
Assigned CSA avatar + name
Click → opens Account Detail page at /accounts/[id]

Account Detail page (/accounts/[id]):
Full page inside AppShell. Two-column layout:
Left column:

Business name, vertical, state, payroll, headcount
GhostButton "Edit" — inline edit, saves to Supabase
Associated deals list — each deal shown as a mini card linking to that deal's Pipeline card (clicking opens DealCardModal)
Associated policies list (pulls from policies table — display only for now)

Right column:

Contact info: primary contact name, email, phone (editable)
Account status (Prospect / Active Client / Inactive) — dropdown, saves to Supabase
Notes field — freeform text, saves to Supabase
Activity log for this account (reuse the activity feed pattern from DealCardModal — same component if possible)

Supabase — accounts table:
id                uuid, primary key
business_name     text
vertical          text
state             text
annual_payroll    numeric
headcount         integer
account_status    text  ('Prospect', 'Active Client', 'Inactive')
primary_contact   text
contact_email     text
contact_phone     text
notes             text
assigned_csa      uuid, references auth.users
created_at        timestamptz, default now()
updated_at        timestamptz, default now()
Link deals to accounts: add account_id uuid references accounts(id) column to the deals table.

PART B — IMPLEMENTATIONS MODULE
Route: /implementations
Accessible to: Admin, CSA roles only.
Trigger: When a deal is moved to Stage 9 (Bound) in the Pipeline, automatically create the appropriate implementation tracker records in Supabase. If quote type is WC or PEO, always create the WC Bind Journey tracker. If quote type is PEO, also create the PEO/ASO Onboarding tracker.
Page layout:

SectionHeader: "Implementations"
Two tabs: "WC Bind Journey" | "PEO / ASO Onboarding"
Each tab shows a list of active trackers as GlassCards

WC Bind Journey tracker card:

Business name + bound date
Progress bar showing current phase out of 4 (use #E91E8C for filled portion, solid — no gradient)
Phase labels below progress bar:

Phase 1: Binder Issued
Phase 2: Policy Documents Sent
Phase 3: Client Signature
Phase 4: Policy Active


Current phase status (In Progress / Complete)
GhostButton "Advance Phase" — moves to next phase, logs to activity feed on the associated deal
Expected completion: 5–7 days from bound date — show days elapsed

PEO / ASO Onboarding tracker card:

Business name + bound date
Progress bar showing current phase out of 5
Phase labels:

Phase 1: Welcome & Kickoff
Phase 2: Data Collection
Phase 3: System Setup
Phase 4: Payroll Parallel Run
Phase 5: Go Live


GhostButton "Advance Phase"
Expected completion: 22+ days from bound date — show days elapsed

Supabase — implementation_trackers table:
id                uuid, primary key
deal_id           uuid, references deals(id)
tracker_type      text  ('WC' or 'PEO')
current_phase     integer, default 1
total_phases      integer  (4 for WC, 5 for PEO)
status            text  ('In Progress', 'Complete')
bound_date        timestamptz
completed_at      timestamptz
created_at        timestamptz, default now()
updated_at        timestamptz, default now()
When all phases complete: set status to 'Complete', log to deal activity feed, and move the associated deal to Stage 10 (Client) automatically.

PART C — BILLING MODULE
Route: /billing
Accessible to: Admin only.
Page layout:

SectionHeader: "Billing", subtitle showing total active premium under management
Two tabs: "WC Premiums" | "Workforce Solutions Fees"

WC Premiums tab:

List of all bound policies (from policies table) as GlassCards
Each card: business name, state, WC premium amount, policy effective date, carrier, status badge
Summary StatTile row at top: Total Premium, Total Policies, Avg Premium

Workforce Solutions Fees tab:

List of all active PEO/ASO clients
Each row: business name, headcount, monthly WFS fee, annual WFS fee, PEPM rate
Summary StatTile row at top: Total Monthly WFS Fees, Total Active PEO Clients

Both tabs:

Search/filter by business name
Export button (GhostButton "Export CSV") — generates a CSV download of the visible list

Supabase — policies table:
id                uuid, primary key
deal_id           uuid, references deals(id)
account_id        uuid, references accounts(id)
policy_type       text  ('WC', 'PEO', 'ASO')
carrier           text
wc_premium        numeric
effective_date    date
expiration_date   date
status            text  ('Active', 'Cancelled', 'Expired')
created_at        timestamptz, default now()
